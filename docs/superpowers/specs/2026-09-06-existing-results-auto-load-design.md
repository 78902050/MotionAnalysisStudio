# 已处理结果自动装载设计

## 目标

登记 Pose2Sim/Caliscope 已处理目录后，用户无需重新运行分析即可看到目录中已经存在的二维姿态、人物关联、三维轨迹和运动学产物。缺少 `Config.toml` 只限制 Pose2Sim 重跑，不限制结果浏览、质检和派生指标计算。

## 已确认问题

- 多试次根目录被“读取单个已处理文件夹”拒绝，用户必须事先知道要改用“扫描上级文件夹”。
- 已有 `manifest.json` 时登记器直接返回，旧清单不会依据现有产物刷新。
- 二维修正只能从可定位的质量问题进入，不能直接浏览已有 pose 帧。
- 二维质量报告只在首次登记后异步生成；旧清单和批量登记的大多数试次没有报告。
- 三维运动学只在点击计算后读取第一个 TRC；事件和对比页只接受本次运行产生的内存指标。
- 已有 `pose-associated`、TRC、MOT/STO 和衍生视频没有统一目录提供给界面。

## 方案

新增只读的 `ProjectArtifactCatalog`。它扫描一个试次的标准目录，返回相机及帧范围、二维层、TRC、MOT/STO、源视频、衍生视频和 Config 状态。清单登记、页面初始化和诊断共享这一个目录事实来源，避免各页面重复猜测路径。

登记器改为幂等刷新：没有清单时创建项目；已有清单时打开并保留项目 ID、修正历史和用户状态，然后用当前目录产物补齐相机、导入报告和已完成阶段。只有缺少活动标定时才导入找到的标定文件，重复登记不触发下游失效。

“读取已处理文件夹”先判断单试次；若目录本身不是试次但包含多个候选，则转为后台扫描并显示候选，不创建空项目。候选登记完成后打开所选试次。

二维修正增加直接浏览入口。打开项目时从 pose 帧建立相机和帧范围；选择相机或移动时间轴会读取对应原始 pose JSON，默认选择第一位人物和第一个有效关节点。26 点数据使用 Pose2Sim `HALPE_26` 名称；不能可靠识别模型时显示 `index-NNN`，不伪造语义。所有保存、备份、撤销和选择性重跑继续复用现有 `CorrectionSession`。

质量扫描以目录中的 pose 和 TRC 为事实来源。缺少报告时自动在后台生成；TRC 提供三维覆盖帧、有效率和缺失率，不再因缺少内部 `pose-3d/results.json` 把真实三维结果视为空。

三维运动页在项目打开时列出全部 TRC 与 MOT/STO，选择 TRC 后在后台计算基础指标。计算完成后发出 `MetricTable`，主窗口把它传给事件页，并为当前项目/试次建立一个对比成员。MOT/STO 先提供文件目录和只读预览，不把 OpenSim 角度误解释为三维坐标。

人物关联页在打开已有结果项目后后台扫描标准 `pose`、`pose-sync`、`pose-associated`；现有语义关联与轨迹段直接显示，未确认候选仍需人工确认。媒体页列出源视频和衍生视频，二维编辑只把原始视频作为背景，避免把带骨架覆盖的视频当作原始证据。

## 后台与错误处理

- 目录扫描、质量分析、人物关联、TRC 解析和指标计算不在 GUI 主线程执行。
- 项目 ID 与 generation 隔离迟到结果；切换项目或关闭窗口时取消任务。
- 单个损坏文件显示具体路径和原因，其余可读产物仍可浏览。
- 清单刷新使用原子写入，不删除已有字段、历史或用户确认结果。
- 空/无效 Config 在流程页显示原因并禁用运行按钮，其他页面保持可用。

## 验收

- 重新登记带旧清单的试次后，相机、二维、同步、关联、TRC 和运动学计数得到修复，项目 ID 与历史不变。
- 读取 `D:\test\data` 自动显示 14 个候选，不创建根目录项目。
- 打开任一完整试次后，二维页面可直接显示真实 pose 点；不需要先生成质量问题。
- 缺少质量报告时后台生成，完成后二维和三维质检页刷新。
- 运动学页显示 TRC/MOT/STO 清单，TRC 指标完成后事件和对比页得到可用输入。
- 空 Config 只禁用重跑。
- 完整单元测试、`compileall`、真实数据副本验收和 EXE smoke 通过。

## 已知限制

- 没有原始视频时二维姿态只显示在坐标空间中；衍生视频可预览但不作为人工修正的原始背景。
- 不能唯一识别的二维骨架模型使用索引标签，需要有效 Config 或用户显式指定后才能得到语义名称。
- 单个项目只自动建立当前试次的对比成员；跨项目批量对比仍由用户选择项目集合。
