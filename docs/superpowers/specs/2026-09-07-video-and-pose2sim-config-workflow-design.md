# 视频导入与 Pose2Sim 配置工作流设计

## 目标

将“视频素材”明确改造成 Pose2Sim 的分析输入管理界面，并将 Pose2Sim 配置从手工粘贴文本改造成“选择文件、复制到项目、结构化编辑、中文说明、源码兜底”的完整工作流。

## 已确认问题

1. 当前文件夹导入只按已有 `camera_id` 与文件名前缀做严格匹配，因此常见的 `1`、`cam1`、`cam01`、`camera01` 命名差异会产生“已绑定 0 台相机，未使用视频 4 个”。
2. 当前绑定只把外部视频绝对路径写入 `manifest.json`。Pose2Sim 不读取该字段，而是扫描运行项目根目录下的 `videos`，所以“界面已绑定”不等于“Pose2Sim 能分析”。
3. 项目配置保存在 `config/Config.toml`，Pose2Sim 接收配置文件路径时会把配置文件所在目录视为 `project_dir`，从而错误读取 `config/videos` 并把结果写入 `config/pose` 等目录。
4. 流程页面只有一个空白或已有文本编辑器，没有选择现有 `Config.toml` 的入口；用户只能复制粘贴。
5. 纯文本编辑虽能改内容，但缺少参数类型、候选值、用途和影响提示，容易出现语法正确但语义错误的配置。

## 固定决策

- 导入的视频是 Pose2Sim 分析输入，界面统一称为“视频”或“分析视频”，不再称为“原视频”。二维修正页面中的“原视频帧”仍表示时间轴语义，不受此文案修改影响。
- 视频复制到 `<项目根目录>/videos`；不修改、不转码用户选择的外部视频。
- 导入的 `Config.toml` 复制到项目清单指定的 `config/Config.toml`，之后只编辑项目副本，外部文件保持不变。
- 指定的 Pose2Sim `Demo_SinglePerson/Config.toml` 是参数和英文注释的语义参考。参数界面的悬浮说明只显示人工整理后的中文内容，不显示英文原注释。
- 项目副本保留导入文件的原始文本、注释和章节顺序；界面层不通过翻译重写 TOML 文件。
- 使用 `tomlkit` 编辑结构化值，以保留格式、注释、章节顺序和未知字段；使用 Python `tomllib` 做运行前语法验证。
- Pose2Sim 运行时始终把 `project_dir` 设置为当前项目根目录。配置页中的该参数显示为项目托管项，不能把输出重定向到其他项目。
- 所有视频复制和媒体探测在后台任务中运行；GUI 主线程只选择文件、确认映射、显示进度和接收结果。

## 视频导入设计

### 用户流程

“视频素材”页面保留一个主操作“导入视频”，调用多文件选择器，支持 `.mp4`、`.avi`、`.mov`、`.mkv` 和 `.m4v`。选择后先生成导入计划，再执行复制：

1. 排除名称含 `_pose`、`_sync`、`_tracked`、`_calibration` 的派生视频，避免把 Pose2Sim 输出再次作为输入。
2. 将相机名规范化后进行唯一匹配。规范化只处理可解释的等价形式，如大小写、空格、连字符以及 `cam`/`camera` 前缀和数字前导零。
3. 剩余视频数与剩余已有相机数相等时，按自然排序生成候选映射并展示确认摘要；未经用户确认不按顺序写入。
4. 项目没有相机记录时，以视频文件名 stem 创建相机记录。
5. 数量不等且无法唯一映射时，仍可复制视频，但明确列出未映射文件，不伪造相机对应关系；Pose2Sim 三维阶段运行前必须提示相机/标定数量不一致。

目标文件固定为 `<项目根目录>/videos/<相机名><原扩展名>`。语义匹配或顺序确认后使用相机名命名目标文件，确保 Pose2Sim 的自然排序与项目相机顺序一致。无相机清单时保留文件名。

复制先写入同目录临时文件，flush 后原子替换。目标存在时在执行前统一选择“跳过已有文件”“替换项目副本”或“取消”；不逐文件弹出对话框。取消时清理未完成临时文件，已完成文件保留并在结果中报告。

### 数据接口

`VideoImportService.plan(project, paths)` 返回不可变 `VideoImportPlan`，包含来源、目标、相机、匹配方式、冲突和警告。`execute(project, plan, replace_existing, token, progress)` 执行复制并在全部成功项确定后一次更新相机清单。清单中的 `video_path` 使用项目相对路径，便于项目跨电脑移动。

## Config.toml 导入与编辑设计

### 文件导入

流程页面新增“导入 Config.toml”。选择文件后先以 UTF-8 读取并验证 TOML；有效文件通过现有备份与原子替换机制写入项目副本。导入成功后同时刷新结构化参数页和源码页。无效、不可读或非文件输入不会改变当前项目配置。

### 双视图

中间配置区使用两个标签页：

- “参数设置”：默认页，按 `[project]`、`[pose]`、`[synchronization]` 等章节组织成可折叠参数树。
- “TOML 源码”：保留完整文本编辑，支持复杂数组表、自定义骨架和多行模型字典。

参数树第一列显示 `ⓘ 参数名`，第二列显示值，第三列显示类型或单位。鼠标悬停第一列只显示中文说明，包括用途、允许值、单位、影响阶段和常见调整后果。

标量、布尔值和普通列表可在参数树中编辑；数组表、复杂内联字典和多行字符串标记为“请在源码页编辑”。布尔值和已知枚举使用下拉框，数值和字符串使用类型校验编辑器。任何修改都会生成新的 TOML 文本并再次解析，只有解析成功才进入文档状态。

源码页修改后，在切回参数页或保存时重新解析。语法错误保留用户文本但禁用保存和运行，并显示行列信息；不会用上一次有效内容静默覆盖。

### 中文帮助

`parameter_help_zh.py` 以完整路径（例如 `pose.det_frequency`）索引中文元数据。内容根据用户指定的 Pose2Sim 0.10.49 单人示例配置人工翻译和整理，不在界面展示英文注释。至少覆盖示例文件中的所有可编辑标准参数；对未知参数显示中文通用说明“自定义参数，请依据所用 Pose2Sim 版本确认含义和取值”。

### 自定义参数

“添加自定义参数”对话框收集章节、键名、TOML 值和中文说明。值先作为独立 TOML 片段解析，再写入文档；重复键、空键和非法章节被拒绝。自定义中文说明保存到 `config/parameter_help.zh.json`，项目重开后继续可见。删除操作只针对用户明确选中的参数，执行前确认，并保留 Config 备份。

## Pose2Sim 运行目录

流程启动不再把配置文件路径直接交给 Pose2Sim。子进程读取项目副本为字典，将 `config["project"]["project_dir"]` 覆盖为当前项目根目录，再调用所选阶段。外部 Pose2Sim Python 与冻结 EXE 的入口使用同一参数：配置路径和项目根目录必须同时提供。

运行前对二维姿态估计检查 `<项目根目录>/videos` 至少存在一个可读视频；对同步及三维阶段检查相机、视频和标定数据的一致性。检查只报告可达问题，不增加无运行价值的哈希或指纹。

## 界面布局

沿用现有深色工作台和三栏可调分栏：左侧阶段、中间配置、右侧实时日志。中间栏顶部放置“导入 Config.toml”“保存配置”“重新载入”，下方是双视图标签。参数树和源码编辑器各自滚动，620×480 时所有操作仍可通过滚动访问。

视觉签名是参数名前的青蓝色 `ⓘ`：它承担说明入口，不增加常驻说明面板，避免重复出现拥挤和频繁上下滚动。

## 错误和恢复

- 视频读取、复制或目标写入失败：报告具体文件和原因，源文件不变。
- Config 导入失败：当前项目副本不变。
- 参数编辑失败：保留编辑中的值并标红，不提交到文档。
- Pose2Sim 启动前目录检查失败：不创建子进程。
- 项目切换、窗口关闭或取消导入：取消后台任务并清理临时文件。
- 已保存 Config 修改和导入均产生独立备份，可从 `config/backups` 人工恢复。

## 测试与验收

- `unittest` 覆盖相机名规范化、自然顺序确认、项目相对路径、重名处理、取消和中文路径。
- 覆盖 Config 导入成功、语法错误、原文件不变、备份、注释/顺序保留、未知参数保留和自定义帮助持久化。
- Qt 测试覆盖按钮文案、多文件选择、参数树编辑、中文 tooltip、源码同步、小窗口滚动和任务取消。
- 子进程命令测试必须证明配置字典中的运行时 `project_dir` 是项目根目录，且 Pose2Sim 从 `<项目>/videos` 读取。
- 完整回归、`compileall`、冻结 EXE smoke 和 `D:/test/data` 已处理项目读取必须通过。
- 真实视频写入验收只在测试项目副本中进行，不修改外部源视频。

## 已知限制

- 应用不自动翻译任意第三方自定义参数；未知参数使用中文通用说明，用户可填写项目级中文说明。
- 自定义骨架数组表和三引号模型字典保留在源码页编辑，避免用不完整的表单破坏结构。
- 数量不一致且名称无法唯一匹配时，不自动猜测相机对应关系。
