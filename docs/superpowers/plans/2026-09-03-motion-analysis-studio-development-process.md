# Motion Analysis Studio 编程规范与阶段执行流程

## 1. 开发单元

每个功能以一个可独立验收的任务为单位。任务必须包含领域模型、失败测试、最小实现、聚焦测试、回归测试和提交；没有测试的功能不进入下一任务。

任务之间通过公共数据契约交接，不通过 GUI 对象、全局变量或隐藏文件名交接。跨模块调用必须经过应用服务或适配器。

## 2. Python 约定

- Python 3.12，启用类型注解和 dataclass。
- 领域层禁止导入 PySide6、OpenCV 和外部进程模块。
- 文件路径统一使用 pathlib.Path；清单内部保存相对路径。
- JSON 读写统一使用 UTF-8；浮点值按文件格式要求序列化，禁止把 NaN/Infinity 写入标准 JSON。
- 外部输入先校验，再转换为内部对象；单个坏人物、坏帧或坏关节点必须保留错误上下文。
- 异常使用带错误码的领域异常；GUI 只展示人类可读信息，不解析异常字符串猜测状态。
- 不使用模块级可变单例保存当前项目、当前相机或当前任务。

## 3. PySide6 约定

- GUI 线程只负责构建控件、处理用户输入和消费信号。
- 长操作使用 QObject worker + QThread 或任务中心；禁止在槽函数中执行全量目录扫描、VideoCapture.read、NumPy 全量计算或 subprocess.wait。
- 每个异步结果必须带 project_id、generation 和 task_id。
- 页面卸载时断开信号、请求取消并等待线程；不能只删除 Python 引用。
- 页面布局使用布局管理器、QSplitter、QScrollArea 和 QSizePolicy；禁止绝对坐标。
- 所有用户可配置尺寸、步长、视图路数和筛选项保存到 QSettings，项目数据不混入 QSettings。

## 4. 业务代码审查清单

提交前检查：

- 是否使用了语义地址，而不是裸数组索引？
- 是否把 raw、synchronized、pose2d、pose3d 时间轴混在一起？
- 是否把轨迹段误显示为项目人物？
- 是否在相机名分支中写死了偏移？
- 是否在多个候选中自动选择第一个？
- 是否在失败时静默跳过坏输入？
- 是否有原子写入、首次备份和恢复历史？
- 是否把外部调用放到后台？
- 是否会在切换项目后用旧任务结果覆盖当前状态？
- 是否为新行为增加了失败测试和回归测试？
- 是否新增了不可导出的绝对开发路径？

## 5. 阶段执行模板

每个阶段按照以下顺序：

1. 阅读本阶段路线图、数据契约和相关前置测试。
2. 在 test-records 中建立本阶段记录文件。
3. 写第一个失败测试并运行，保存失败输出。
4. 实现最小数据模型和服务。
5. 运行聚焦测试。
6. 实现 GUI 和后台任务绑定。
7. 运行阶段完整测试、compileall 和 GUI heartbeat。
8. 用真实项目副本做最小可行性验收。
9. 更新需求追溯矩阵、决策记录、已知限制和文档状态。
10. 建立 Git 提交和独立源码归档。
11. 从归档解压到新目录，再运行一次测试确认归档可用。
12. 才能进入下一阶段。

## 6. 提交命名

- chore: 项目骨架、工具和文档
- feat: 新领域功能
- fix: 已验证的缺陷修复
- test: 测试和夹具
- docs: 设计、计划和记录
- release: 阶段或最终发布

每个提交消息后附阶段和需求 ID，例如 feat: add semantic quality audit [phase-1 R-010]。

## 7. 评审要求

每个阶段完成前进行两轮检查：先由实现者对照需求追溯矩阵自检，再由独立审查者检查数据语义、线程边界、异常恢复和测试覆盖。发现问题必须先补失败测试，再修代码；不能仅修改测试使其通过。

## 8. 文档变更规则

数据字段、枚举或阶段失效规则变化时，必须同时更新总体设计、数据契约、实现计划、追溯矩阵和对应测试。界面布局变化时，必须更新界面设计和窗口尺寸测试。文档状态只能使用“计划中”“实现中”“已验收”“受阻”四种明确状态。
