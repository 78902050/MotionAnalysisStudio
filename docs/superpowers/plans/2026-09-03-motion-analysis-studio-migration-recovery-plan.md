# Motion Analysis Studio 迁移、备份与恢复计划

## 1. 目的

本计划解决三个风险：旧项目如何安全打开、用户数据如何在修改失败时恢复、源码和文档如何避免因工作区重挂载再次丢失。

## 2. 源码工程保护

重建开始前必须在项目根目录执行以下顺序：

1. 初始化 Git 仓库并确认 .git 位于项目根目录。
2. 建立 clean baseline 提交，提交文档、骨架和测试夹具。
3. 创建项目源码压缩归档，归档中排除虚拟环境、视频、Pose2Sim 输出和用户数据。
4. 在每个阶段完成后创建一个独立提交和一个独立源码归档。
5. 在进入下一阶段前，在归档目录中解压到新临时目录并运行一次 compileall，确认归档可用。
6. 记录当前工作区绝对路径、提交 ID、归档路径和测试记录。

归档脚本只复制项目源码、配置模板、文档、测试和构建脚本；不复制原始视频或真实项目数据。用户已明确不要求每次检查文件 SHA-256，因此不把 SHA-256 作为交付门禁；功能所需的标定内容指纹仍然保留，用于判断导入内容是否变化。

## 3. 项目数据保护

- 原始 MP4 只读打开，禁止写入和转码。
- 外部标定文件只读解析；导入前显示路径、大小、修改时间和内容指纹。
- Pose2Sim 和 Caliscope 安装目录只读；所有适配逻辑在 app/adapters 下。
- 真实项目验收必须先复制到带唯一 ID 的临时目录；原始 D:\test\test 不作为工作目录。
- 任何“保存并重跑”操作先写审计记录和阶段快照，再启动任务。
- 关闭窗口时如果任务未完成，先取消并等待；无法清理时显示任务 ID、阶段和日志，不假装已关闭。

## 4. 项目 v2 到 v3 迁移

迁移顺序：

1. 以只读方式加载旧 manifest。
2. 复制旧 manifest 到 migration/backups，并保留原始文本。
3. 检查旧路径是否存在、JSON 是否有效、旧字段是否完整。
4. 添加 schema_version 3、project_id、阶段状态、paths、cameras、people 和 migration 字段。
5. 创建 corrections、reports 和 logs 目录；目录已存在时不覆盖内容。
6. 原样保留 manual_pose_edits、已有报告和 Pose2Sim 结果。
7. 原子替换 manifest，写迁移记录。
8. 重新读取 manifest 并运行结构校验。
9. 重复打开时返回 no-op，不重复写入同一迁移记录。

迁移失败时保留旧 manifest，清理只允许针对本次创建且为空的临时文件；不能删除用户已有目录。

## 5. 修正数据恢复

工作 JSON 保存事务：

1. 生成唯一 transaction_id 和 session_id。
2. 以独占创建方式保存首次备份；备份存在时只校验可读，不覆盖。
3. 写临时 JSON 并 flush、fsync。
4. 原子替换工作 JSON。
5. 追加每个操作的 before/after、目标地址、备注、用户来源和时间。
6. 更新阶段失效状态和 manifest。
7. 写事务完成标记。

任何一步失败都必须报告 transaction_id、文件路径和失败步骤。启动时扫描未完成事务：如果工作文件可读且备份可读，给用户“恢复备份 / 保留当前文件 / 查看日志”三个选项；默认不静默覆盖。

## 6. 恢复层级

- 当前帧恢复：只清除本次会话尚未保存的内存操作。
- 当前文件恢复：把首次备份恢复为工作文件，同时追加 source=restore 的历史操作。
- 批次恢复：用户明确选择文件或 operation_id，逐文件执行可回滚恢复；任何失败都保留已完成文件清单。
- 关联恢复：除了 constraints，还必须恢复 pose-associated 物化结果；恢复后重新校验 fingerprint。
- 报告恢复：旧报告文件不删除，新的报告以版本号保存并把当前状态标记为 stale 或 restored。

## 7. 外部任务恢复

任务记录包含 project_id、generation、task_id、stage、command、log_path 和状态。任务完成回调必须先比较当前项目和 generation；不匹配时只保存日志，不更新当前界面或 manifest。取消时依次请求 worker、子进程和解码器停止，并在最终回调中关闭线程。

## 8. 工作区丢失的预防

每次阶段完成前执行：

- Git status 检查；
- 归档脚本；
- 在新目录解压归档；
- 运行聚焦测试、完整 unittest 和 compileall；
- 更新 test-records 和 decision-log；
- 将归档路径回填到阶段记录。

若工作区发生重挂载，先停止代码修改，定位最近归档和提交；不能直接从残缺目录继续。会话日志只作为补丁恢复的辅助证据，不能替代源码归档。

## 9. 发布恢复包

诊断包仅包含脱敏后的 manifest、阶段状态、质量报告摘要、错误信息、版本和日志索引。默认排除视频、原始标定、Pose2Sim 全量输出和用户姓名；用户必须主动选择才可以附加指定文件。恢复包在导入新电脑后先进行路径检查和能力检查，再允许执行阶段任务。
